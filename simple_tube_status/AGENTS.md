# Simple Tube Status plugin

Read the root `AGENTS.md` first for repo-wide rules, secrets and TRMNL platform facts.

## Data source and severity

- Data source: TfL Unified API, `GET https://api.tfl.gov.uk/Line/Mode/{{ modes }}/Status`. Free, no key. The array response arrives as `data`; a 400 for an unknown mode arrives as a top-level object with `message`.
- `shared.liquid` sets `api_error` from the top-level `message` field, since that is where the 400 body normally arrives, and falls back to `data.message` to cover a body that TRMNL wraps under `data`.
- Severity rule: a `lineStatuses` entry is disrupted when `statusSeverity` is not 10, 18 or 20. Do not use "below 10"; it misses 11 to 17 and 19.
- Each disrupted line renders exactly one row, whether in the single table or in compact mode's two-column tables, never one per disrupted status entry. `shared.liquid` picks that line's worst entry with its own worst-first ranking of severity codes: `1, 2, 16, 3, 4, 5, 11, 6, 8, 7, 15, 14, 9, 12, 13, 17, 0, 19` (`severity_rank`, defined once at the top of the `board` template). A status code missing from that list ranks after every listed code (fallback rank 99); among entries with an unranked code, or on a tie, the first as TfL lists them wins.
- Verified against the live API on September 4, 2026: endpoint, field names, severity codes and the 400 error shape.

## Board modes and fitting

- The four layouts pass text and table classes and `max_name_chars`; there are no per-layout reason or row caps.
- Whenever there are disrupted lines, the board renders three things inside `.layout`: the single table in `<div data-board="table">`, the compact block in `<div class="hidden" data-board="columns">`, and `<span ... data-board="foot">Good service on all other lines</span>`. The table and compact block sit inside one `grow w--full` wrapper that pushes the footer down. Empty, error and all-good states keep their own markup.
- The single table has one row per disrupted line. With the reason toggle on, every row includes the chosen entry's reason under the name in a `label lg:label--xxlarge lg:portrait:label--large block` span with `data-board="reason"` and `data-clamp="1"` (one line, ellipsis; the block class supplies the line break, so there is no `<br>`). With the toggle off, no reason span renders.
- The compact block contains two side-by-side tables (`.columns` / `.column`), each a name-left, status-right list with no `<thead>` or reasons. The disrupted lines split column-major: the first `half` (`(disrupted + 1) / 2`, integer division) fill the first table in TfL order, the rest fill the second, always with short names. Both rendered blocks use the same per-line severity selection, each loop run once.
- An inline script at the end of the board template scopes itself with `document.currentScript.closest(".layout")`, so several views in a mashup fit independently. Its `fit()` is idempotent: first restore the reason spans' inline display, show the table and hide the compact block; if the footer's bottom is more than 1px below the layout's bottom, hide every reason span; if it still overflows, hide the table wrapper and show the compact block. The script runs on `document.fonts.ready` and again through a `ResizeObserver` on the layout, so a later resize can restore the table or reasons.
- Reasons are hidden with inline `style.display = "none"`, because their framework `block` class would fight `hidden`. The compact block's `hidden` class belongs on its plain wrapper div, not the `.columns` element itself: `.columns` sets `display:flex` at the same specificity as `.hidden`.
- Measured with console logging in the editor on September 13, 2026: at window `load`, `document.fonts.status` was still `loading` and the preview was still at the default 800x480 geometry, with layout bottom 421px. The editor applies the selected device and orientation after load by mutating the same document, so a load-only script measured the wrong screen and could not undo its decision. The framework's `.layout` is a fixed-height flex column with `overflow:hidden`; compare the footer and layout bottom edges. `scrollHeight` was 2px larger than `clientHeight` even without overflow, so it is not used.
- The editor's live preview runs inline scripts, confirmed September 13, 2026; console output is visible under the editor's JS Logs button and in the preview frame's console. The device render is a headless browser screenshot after load, which is also what the framework's `data-clamp` and `data-table-limit` rely on.
- The reviewer's September 2026 eight-line day exposed the old caps: half horizontal showed compact columns on the X in portrait even though a single table fit. The script measures the actual geometry, so orientation, text scale and mashup size all determine whether reasons or the table fit.
- Compact mode has no further overflow guard, so when nearly every line is disrupted it can run past the bottom of smaller boards; that is the accepted trade-off for never hiding a line. The table carries no `data-table-limit`; the fit script controls the switch to compact mode.
- Historical original-device measurements from the markup editor on September 7, 2026 (true device pixels) were full board 359px, header 24px, name-only row 42px and reason row 62px; half horizontal board 144px, row 31px and reason row 51px; half vertical board 374px, row 31px and reason row 51px. On the X full layout a reason row measured 106px, so an eight-row table with reasons needed 926px in a 711px board. These explain the space pressure; the script now measures each render.
- The title bar is a sibling placed after `layout`, so it renders as a footer, unlike National Rail which nests it. The good-service state uses `flex flex--center-x flex--center-y stretch-y`, not a nested `layout`.

## Text sizes and badges

- Status badges and text-size classes all carry matching `lg:`/`lg:portrait:` variants, mirroring the pattern National Rail Departures uses; the bullets below say how the badge is built and sized per device. The `lg:` breakpoint is 1024px min-width; the TRMNL X has a physical resolution of 1872x1404.
- The status badge sits right-aligned in the second column, whose `<td>` carries `style="white-space:nowrap"` because the framework has no no-wrap utility and the table's auto column split otherwise wrapped "Part Suspended" onto two lines on the halves (measured September 7, 2026).
- Text size classes on the original device: full uses `value value--base` names (38px on a 42px line) with a badge of the same size; both halves use `value value--small` names (26px) with a `value--xsmall` (20px) badge; the quadrant uses `label` with a plain `label label--inverted` badge.
- In the single table on full and the halves the badge is not a `label`: the label family tops out at `label--xxlarge` (30px), which looked half-size next to the X's 58px names, so the badge is a `value`-sized span built from the framework utilities `bg--black text--white rounded--xsmall px--1` (label--inverted's own styling is 4px corners and 1px 5px padding, so this is a close match).
- Width sets the badge size: on the X full table "Hammersmith & City" at 58px is about 620px, so beside "Part Suspended" the badge can be `lg:value--base` (about 300px) but not `lg:value--large`; on the 500px-wide X halves the short names leave room for `lg:value--small`.
- The reason line is `label lg:label--xxlarge lg:portrait:label--large` (16px on the original device, 30px on the X).
- Half vertical's compact columns (about 180px wide) keep the `label label--inverted` badge, and the quadrant uses that badge family with the smaller compact sizes below, because nothing larger fits.
- The quadrant's compact columns are 177px wide on the original device and 237px on the X (measured September 13, 2026 in the editor's preview frame). At `label` (16px) "Suffragette" plus a "Planned Closure" badge needs about 235px, and at `lg:label--large` (21px) about 290px, so both devices overflowed and the second column was clipped (the TRMNL reviewer's screenshots). The compact `col_class` is therefore `label label--small lg:label--base lg:portrait:label--small`, and `col_badge_class` adds `label--inverted`: 12px on the original device (the widest row then needs 172px) and 16px on the X (227px). The X in portrait has quadrant columns as narrow as the original device, hence the portrait override.
- Compact-mode cells carry no `pl--1`/`pr--1`: with them the widest original-device quadrant row was 180px in a 177px column. The single table keeps its cell padding.
- The halves cannot take 38px: measured September 7, 2026, a 385px-wide half wrapped the badge, "Elizabeth line" and the footer at that size.
- Each layout passes `cell_class`, `badge_class`, `foot_class`, `col_class` and `col_badge_class`; compact mode uses the `col_` pair because each column is half the width. Full and half horizontal use `value value--small lg:value--base lg:portrait:value--small` names with `value value--xsmall lg:value--small lg:portrait:value--xsmall bg--black text--white rounded--xsmall px--1` badges; half vertical uses `value value--xsmall lg:value--base lg:portrait:value--small` names with `label label--inverted lg:label--large lg:portrait:label--base` badges; the quadrant uses the smaller label classes above. A September 7, 2026 editor render showed why compact sizes are needed: full's 38px names and 30px badges wrapped inside 390px columns.
- The footer "Good service on all other lines" uses `foot_class`, which matches `cell_class` on the original device everywhere except half vertical, where it drops to `value value--xsmall` so the sentence stays on one line at 385px.
- The full layout's table uses `table--small` on both devices, its layout carries `gap--none`, and its footer is `lg:value--base` on the X: with nine rows at `lg:value--large` (70px lines) the table ends 45px above the board's bottom, so a 70px footer plus the layout's 10px gap clipped into the title bar (measured September 7, 2026). That day's nine-line static test also pushed the footer into the title bar with `lg:table--base` padding; keeping `table--small` on the X lets the nine-row table use the space that compact columns at `lg:value--base`, constrained by column width, leave mostly empty.
- Half vertical's footer is `lg:value--small lg:portrait:value--xsmall` on the X because "Good service on all other lines" wrapped at `lg:value--base` in its 500px-wide X preview.
- The error-state heading follows the layout's `head_class`.

## Short names

- Short names are "H&C", "W&C", "Elizabeth" and "Met" for Hammersmith & City, Waterloo & City, Elizabeth line and Metropolitan.
- In the single table a row uses the full name when its character count is within the layout's `max_name_chars` budget and the short name otherwise; Liquid cannot measure text, so the budget stands in for width.
- Budgets: full 99 and quadrant 99 (never shorten), both halves 13 (shortens the 14-, 15- and 18-character names; "Metropolitan" is 12 and stays).
- Compact two-column mode always uses short names.

## Reason toggle

- Reason text drops everything up to and including its first `": "`, because TfL prefixes every reason with the line name.
- The `show_disruptions` boolean custom field (added September 7, 2026, default off) gates the reason line entirely.
- Custom field values are not top-level template variables: they live at `trmnl.plugin_settings.custom_fields_values.<keyname>`, and a boolean field arrives as the string `"true"` or `"false"` (confirmed September 7, 2026 in the editor: a top-level `show_disruptions` never rendered a reason, and the merge-variables view showed only `data` and `trmnl`).
- `shared.liquid` reads that path, folds it into `show_reason` accepting either the string `"true"` or a boolean, and every layout passes `show_reason` into the `board` render.
- Off, every row is name and status only. On, the script hides all reasons when they do not fit, then switches to compact columns if the table still overflows; the help text in `settings.yml` explains that reasons disappear on a busy day.
- `check.py` renders with the field on by default to check reason markup, and separately proves `"true"` and `True` render one clamped reason per table row while missing, `"false"` and `False` omit every reason.
- The reason toggle is a custom field value, so tick it on the settings page, not through MCP, and untick it afterwards.

## Testing

- Local render check: `python3 simple_tube_status/check.py` (requires the `python-liquid` package; `uv run --with python-liquid python3 simple_tube_status/check.py` works without installing it). It renders all four layouts against seven fixtures. The script must print `ok`.
- One fixture covers the all-good state.
- Another (`DISRUPTED`) covers three disrupted lines, using severities 6, 9, 10, 11, 18 and 20 and prefixed reasons; Piccadilly carries two disrupted entries (9 and 6) that must collapse to one row showing the worse Severe Delays, not Minor Delays.
- A third fixture (`RANK_ORDER`) proves the ranking, not numeric value or TfL's listed order, picks the winner: a line lists Minor Delays (9) before Part Closed (11), and the row must show Part Closed with its reason; a second line carries only an unranked code (42, "Mystery") to prove the fallback still renders it.
- A fourth fixture (`MANY`) uses nine disrupted lines to exercise the uneven column-major split and short names, with nine rows in the single table and five then four rows in the compact tables on every layout.
- A fifth fixture (`FIVE`) holds five disrupted lines, so every layout renders five single-table rows, five reason spans when enabled and compact tables split three then two.
- A sixth fixture holds a 400 error body. A seventh fixture holds an empty payload.
- `python3 simple_tube_status/check.py dump three|five|nine` prints the three static fixtures used on September 7, 2026 ready to paste: three, five or nine disrupted lines. The nine-line fixture also drives the September 13 device and orientation sweep below.
- For every disruption fixture and layout, `check.py` asserts one single-table row per disrupted line, the compact block directly inside its initially hidden wrapper with the column-major split, one reason span carrying `data-clamp="1"` per table row when enabled and none when disabled, and exactly one script mentioning all four `data-board` markers and `document.currentScript`. It also checks status selection, names and row order, reason prefix stripping and escaping, text classes, the grow wrapper, footer, embedded icon and error and empty states. These are Liquid render assertions; browser fitting is checked in the editor.
- To measure real widths and heights, open the markup editor for one size (`/plugin_settings/<id>/markup/edit?size=markup_quadrant`) in Playwright and read `document.querySelector('iframe.rounded-2xl').contentDocument`: it is same-origin, so `getBoundingClientRect()` on `.column`, `table`, `tbody tr` and the spans gives CSS pixels. The X renders at 1040x780 CSS pixels in landscape and 780x1040 in portrait; the original renders at 800x480 and 480x800. Switch device with the toolbar `<select>` whose options include "TRMNL X" (set its value and dispatch a `change` event), and orientation with the "Toggle orientation" button. After either change wait about 1.5s for the `ResizeObserver` to rerun `fit()`, then read `[data-board=table]`'s `hidden` class, the reason spans' inline display, and the footer and layout bottoms. Wait for `document.fonts.status` to be `loaded` before measuring: the original device's bitmap font (`TRMNL12`) is wider than the fallback. Candidate classes can be swapped on spans in that frame and re-measured before writing markup.
- The settings page's Force Refresh link opens an in-page "Are you sure?" modal whose Confirm button must be clicked; `window.confirm` is not used. To enable "Show disruption information", tick the checkbox whose name ends in `[show_disruptions]` on the settings page and click Save.

## Decisions the TRMNL automated reviewer keeps questioning

Do not revisit these without new evidence from a device or the simulator:

- No `data-table-limit` and no custom style block in Simple Tube Status: the limiter hid rows that fit because it reserves its own label row, Rob removed it on September 5, 2026, and the inline fit script now controls overflow. (National Rail Departures still uses its own `.board` style block; that is unrelated to this plugin.)
- No transform script. The Liquid `default` and `size` filters handle empty and error payloads, and `check.py` proves it.
- The inline fit script is deliberate: it replaces orientation-blind row and reason caps with measurements of the rendered layout, first hiding reasons and then selecting compact columns. It runs after fonts settle and whenever the layout resizes. The recipe checker's inline-style warning covers both the status cells' required `white-space:nowrap` and the reason spans' `style.display` toggling; the framework's `block` class prevents using `hidden` reliably on those spans.
- `image-dither` on the icon is harmless on a black silhouette; leave it.
- The Simple Tube Status layouts write the `title_bar` div by hand, as `tfl_bus_times` does, rather than `{% render 'title_bar' %}`. The cheat sheet only requires it to be a sibling of `layout`, and the hand-written version is what the device has shown.
- The recipe checker runs its "no layout class" and "no responsive classes" hints against the shared markup too, where neither belongs. The four layouts carry `layout layout--col`, and TRMNL X sizing uses `lg:` and `lg:portrait:` prefixes on the size classes passed into the board template.
- No validation on the `modes` field. A misspelt mode makes TfL return a 400, and the board shows "Could not fetch TfL status" with TfL's own message naming the bad mode, so the mistake is not silent. The help text already lists all five valid names.
- Compact mode is fixed at two columns on every size, so on a strike day the quadrant (about twelve rows) and half horizontal (about eight) can overrun with nineteen or twenty lines disrupted. Rob accepted that on September 5, 2026: people know when there is a strike. A per-layout column count or a group-by-status stage would be the next step if it ever matters.
